# JYLY — клуб бөлмелерін брондау жүйесі

JYLY — networking кездесулеріне, келіссөздерге, командалық жұмысқа және шағын іс-шараларға арналған
клуб бөлмелерін брондау жүйесі. Java пәні бойынша оқу жобасы: барлық бизнес-логика (баға, депозит,
қос брондаудан қорғау, төлемдер, статустар) Java-сервистерде жазылған, интерфейс толығымен қазақ тілінде.

## Не істей алады

**Клиент үшін**
- бөлмелер каталогы: қонақтар саны, баға, түр, күн мен уақыт бойынша сүзу, баға/сыйымдылық бойынша сұрыптау;
- бөлменің толық беті: сурет, жабдықтар, бос емес уақыттар (7 күн);
- брондау: бөлме, күн, уақыт, қонақтар саны, мақсат, тілектер, ұйымдастырушы, бірнеше қонақ (JS арқылы қосу/жою);
- құн мен депозитті алдын ала есептеу (сервердегі `PricingService` арқылы, JSON API);
- демо төлем: депозит, қалған соманы толық немесе бөліп төлеу, сәтсіз төлемді имитациялау;
- «Брондау тарихы»: брондаулар тізімі, толық ақпарат, қонақтар, төлем тарихы, өңдеу, тоқтату.

**Әкімші үшін (`/admin`, Spring Security арқылы қорғалған)**
- шолу: брондаулар саны, күтілетін/расталған, таза түсім, өтелмеген қалдық, белсенді бөлмелер,
  соңғы 14 күндегі брондаулар мен түсім диаграммалары, соңғы брондаулар;
- бөлмелер: қосу, өңдеу (баға, сыйымдылық, сипаттама, жабдықтар, сурет), белсендіру/өшіру;
- брондаулар: нөмір/клиент/бөлме бойынша іздеу, күн мен статус бойынша сүзу, растау, аяқтау, тоқтату;
- клиенттер және төлемдер тарихы (тек оқу — әкімші төлемдерді өзгерте алмайды).

Барлық CSS, JS, шрифттер, иконкалар және суреттер жобаның ішінде — интернетсіз де жұмыс істейді.

## Іске қосу (Windows, PowerShell)

1. JDK 21+ орнатылғанын тексеріңіз. Егер `java` PATH-та болмаса, `JAVA_HOME` көрсетіңіз, мысалы:
   ```powershell
   $env:JAVA_HOME = "C:\Users\Acer\.jdks\openjdk-25"
   # немесе IntelliJ IDEA ішіндегі JDK 21:
   # $env:JAVA_HOME = "C:\Program Files\JetBrains\IntelliJ IDEA 2025.2.3\jbr"
   ```
2. Жоба папкасында іске қосыңыз:
   ```powershell
   cd C:\Users\Acer\jyly
   .\mvnw.cmd spring-boot:run
   ```
3. Браузерде ашыңыз: **http://localhost:8080**

Алғашқы іске қосқанда демо деректер (4 бөлме, 4 клиент, 6 брондау, 10 төлем) автоматты түрде жасалады.
Деректер `.\data\jyly.mv.db` файлында сақталады; қайта іске қосқанда қайталанбайды.
Демо деректерді басынан бастау үшін қосымшаны тоқтатып, `data` папкасын өшіріңіз.

**VS Code арқылы:** «Extension Pack for Java» кеңейтуін орнатып, папканы ашыңыз да,
Run and Debug панелінен **JYLY (local, H2)** конфигурациясын таңдаңыз (`.vscode/launch.json`).
Немесе VS Code терминалында жоғарыдағы PowerShell командасын орындаңыз.

## Әкімші есептік жазбасы

Әкімші конфигурациядан жасалады, құпиясөз дерекқорда тек **BCrypt хеші** түрінде сақталады.

| Профиль | Логин | Құпиясөз |
|---|---|---|
| `local` (әдепкі) | `admin` | `jyly-demo-admin` — **УАҚЫТША демо құпиясөз**, тек жергілікті тексеру үшін |
| `mysql` | `JYLY_ADMIN_USERNAME` | тек `JYLY_ADMIN_PASSWORD` айнымалысы арқылы (әдепкі мән жоқ) |

Өз құпиясөзіңізді орнату:
```powershell
$env:JYLY_ADMIN_USERNAME = "manager"
$env:JYLY_ADMIN_PASSWORD = "Сенімді-құпиясөз-2026"
.\mvnw.cmd spring-boot:run
```
Айнымалы өзгерсе, келесі іске қосуда хеш жаңартылады. Production-да демо құпиясөзді қолданбаңыз.

## Архитектура

```
src/main/java/kz/jyly
├── config/       баптаулар: JylyProperties (клуб ережелері), Security, Clock, AdminInitializer, DataSeeder
├── controller/   HTML және JSON контроллерлер (admin/ — әкімші бөлімі), Fmt — қазақша форматтау
├── service/      бизнес-логика: PricingService, BookingRules, BookingService, PaymentService, RoomService…
├── repository/   Spring Data JPA репозиторийлері (JPQL, параметрлі сұраулар — SQL инъекциясы жоқ)
├── entity/       JPA сущностары: Room, Customer, Booking, Guest, Payment, AppUser
├── dto/          формалар (BookingForm, PaymentForm, RoomForm…) және көрініс деректері
├── enums/        BookingStatus, PaymentStatus, PaymentType, TransactionStatus, RoomType, Role
└── exception/    BusinessException, BookingConflictException, NotFoundException, GlobalExceptionHandler
src/main/resources
├── templates/    Thymeleaf беттері (fragments/ — ортақ layout, admin/ — әкімші)
├── static/       css/app.css (дизайн-жүйе), js/app.js, js/booking.js, images/, fonts/, vendor/
└── application*.properties
```

Контроллерлер тек HTTP-мен жұмыс істейді; барлық шешімдер сервистерде. Формалар DTO арқылы
қабылданады, `@Valid` + сервистегі қайта тексеру. Ақша мәндері — тек `BigDecimal`.

### Сущностар және байланыстар

- **Room** 1 — * **Booking** * — 1 **Customer**
- **Booking** 1 — * **Guest** (брондаумен бірге сақталады/өшіріледі)
- **Booking** 1 — * **Payment** (каскадты жою жоқ — қаржы тарихы ешқашан өшірілмейді)
- **AppUser** — әкімші (BCrypt хеші, рөл `ADMIN`)

Бөлме өшірілмейді, тек `active=false` болады — брондау және төлем тарихы сақталады. Брондау бағасы
брондау кезінде `hourlyRate` өрісіне көшіріледі, сондықтан кейін бөлме бағасы өзгерсе де ескі сома өзгермейді.
Индекстер: `(room_id, start_date_time, end_date_time)`, `status`, бірегей `booking_number`,
`transaction_reference`, `idempotency_key`.

## Брондау қалай жұмыс істейді

1. Сервер тексереді: бөлме белсенді; күн өтпеген және 90 күннен аспайды; уақыт 08:00–22:00 аралығында,
   30 минуттық қадаммен; ұзақтық 1–12 сағат; қонақтар саны 1-ден көп және сыйымдылықтан аспайды;
   аты-жөні көрсетілген қонақтар саны жалпы саннан аспайды; байланыс деректері дұрыс.
2. **Қос брондаудан қорғау.** Екі аралық қиылысады, егер
   `existingStart < requestedEnd && existingEnd > requestedStart`.
   Тек `PENDING`, `CONFIRMED`, `COMPLETED` брондаулар бөлмені бұғаттайды; `CANCELLED` — бұғаттамайды.
3. Жаңа брондау `PENDING` (Күтілуде) статусымен, `UNPAID` төлем статусымен жасалады.
   Нөмірі кездейсоқ: `JY-XXXX-XXXX` (`SecureRandom`, ~10¹² нұсқа).
4. Қақтығыс болса, брондау жасалмайды; сол күнгі бос уақыттар ұсынылады.

### Параллель сұраулар және шектеулер

`BookingService.create` бір транзакцияда орындалады және алдымен бөлме жолын
`SELECT … FOR UPDATE` (`PESSIMISTIC_WRITE`) арқылы құлыптайды. Сондықтан бір бөлмеге бір уақытта келген
сұраулар кезекпен өтеді: екіншісі біріншісі сақтаған брондауды көріп, қақтығыс қайтарады. Бұл H2-де де,
MySQL/InnoDB-де де жұмыс істейді және тестпен тексерілген (6 параллель сұрау → 1 брондау).

Шектеулер:
- құлып бөлме деңгейінде: бір бөлменің түрлі уақыттарына келген сұраулар да кезекпен өтеді (шағын клуб үшін маңызды емес);
- қорғау қосымша деңгейінде; басқа қосымша дәл сол дерекқорға тікелей жазса, ол қорғалмайды
  (толық кепілдік үшін PostgreSQL-дағы exclusion constraint сияқты дерекқор шектеуі қажет);
- `PENDING` брондаулар депозит төленбесе де уақытты ұстап тұрады; автоматты мерзімі өту іске асырылмаған —
  әкімші оларды қолмен тоқтатады;
- H2 құлыпты күту уақыты `LOCK_TIMEOUT=10000` (10 с).

## Құн мен депозит қалай есептеледі

`PricingService` (барлығы `BigDecimal`, бүтін теңгеге дейін `HALF_UP`):

```
billableHours   = ceil(ұзақтық минут / 60)        — әр басталған сағат толық есептеледі
totalAmount     = hourlyRate × billableHours
depositAmount   = totalAmount × depositPercent / 100
remainingAmount = totalAmount − amountPaid       — ешқашан теріс емес
```

Мысал: Connect Room 12 000 ₸/сағ × 3 сағ = **36 000 ₸**, депозит 30% = **10 800 ₸**, қалғаны **25 200 ₸**.
1 сағ 30 мин брондау 2 сағат ретінде есептеледі.

Барлық ереже `application.properties` ішінде (`jyly.*`): `deposit-percent`, `opening-time`, `closing-time`,
`slot-minutes`, `min-duration-minutes`, `max-duration-hours`, `max-days-ahead`, `free-cancellation-hours`.
Браузердегі алдын ала есеп те серверден (`/api/pricing/quote`) алынады; соңғы сома брондауды сақтағанда қайта есептеледі.

## Төлемдер (ДЕМО режим)

> Нақты банк эквайрингі **қосылмаған**. Карта деректері сұралмайды, **ешқандай ақша есептен шығарылмайды**.
> Әр операция жүйеде «демо» белгісімен тіркеледі. Қайтарулар да тек демо жазба — нақты банк операциясы емес.

- Төлем түрлері: `DEPOSIT` (депозит), `BALANCE` (қалған соманы толық немесе бөліп), `REFUND` (қайтару).
- Операция статусы (`TransactionStatus`): `SUCCEEDED`, `FAILED`, `CANCELLED`. Тек `SUCCEEDED` төленген сомаға қосылады.
- Төлем бетінде «сәтті» немесе «сәтсіз» нәтижені таңдауға болады; сәтсіз операция тарихта сақталады, бірақ есепке алынбайды.
- Артық төлем мүмкін емес: сома > 0, бүтін теңге, қалған сомадан аспайды. Брондау жолы төлем кезінде құлыпталады.
- Бір форманы екі рет жіберу бір рет қана есептеледі: әр формада бірегей `idempotencyKey` бар (дерекқорда unique).
- `amountPaid` әр операциядан кейін `payments` кестесінен қайта есептеледі (сәтті кіріс − сәтті қайтарулар).
- Әкімші төлемдерді жасай да, өзгерте де алмайды.

Брондаудың төлем статусы (`PaymentStatus`): Төленбеген · Депозит төленді · Ішінара төленді · Толық төленді · Қайтарылды.

### Статустар және тоқтату ережелері

```
PENDING ──(депозит төленді / әкімші растады)──► CONFIRMED ──(аяқталғаннан кейін, әкімші)──► COMPLETED
   └──────────────(тоқтату)──────────────► CANCELLED ◄──────────(тоқтату)──────┘
```

- Брондау статусы толық төлем дегенді білдірмейді: төлем статусы бөлек сақталады.
- Клиент тек басталмаған брондауды тоқтата алады. Басталуға **24 сағаттан көп** қалса — төленген соманың бәрі
  қайтарылады; аз қалса — депозит ұсталады, одан артық төленгені қайтарылады.
- Әкімші (клуб тарапынан) тоқтатса — бүкіл төленген сома қайтарылады.
- Тоқтатылған және аяқталған брондаулар мен олардың төлемдері өшірілмейді.

## Қауіпсіздік

- `/admin/**` — тек `ADMIN` рөлі; кіру беті `/login`; құпиясөздер BCrypt.
- Барлық POST формалар CSRF токенімен қорғалған (Spring Security).
- Клиенттер тіркелмейді: брондауға қолжетімділік тек сессияда және тек нақты нөмірге беріледі —
  брондауды жасағанда немесе **нөмір + ұйымдастырушы поштасы** сәйкес келгенде. Тек ID немесе тек нөмір бойынша
  бөтен брондауды ашу мүмкін емес; қате болса, қай өріс қате екені айтылмайды.
- Thymeleaf `th:text` мәндерді экрандайды (XSS жоқ); сұраулар параметрлі JPQL (SQL инъекциясы жоқ).
- Ашық форма бар клиенттің атын/телефонын қайта жазбайды (бөтен поштамен деректерді өзгертуге болмайды).

## MySQL профилі

1. MySQL 8 орнатып, пайдаланушы жасаңыз (дерекқор автоматты жасалады):
   ```sql
   CREATE USER 'jyly'@'localhost' IDENTIFIED BY 'құпиясөз';
   GRANT ALL PRIVILEGES ON jyly.* TO 'jyly'@'localhost';
   ```
2. Айнымалыларды беріп, `mysql` профилімен іске қосыңыз:
   ```powershell
   $env:JYLY_DB_URL = "jdbc:mysql://localhost:3306/jyly?createDatabaseIfNotExist=true&serverTimezone=Asia/Almaty"
   $env:JYLY_DB_USERNAME = "jyly"
   $env:JYLY_DB_PASSWORD = "құпиясөз"
   $env:JYLY_ADMIN_PASSWORD = "Сенімді-құпиясөз-2026"
   .\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=mysql"
   ```
Кестелер `ddl-auto=update` арқылы жасалады. Нақты өндірісте Flyway/Liquibase миграцияларын қолданған дұрыс.
